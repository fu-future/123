# 记账软件 — 产品需求文档（PRD）

## 2. 产品定义

### 2.1 产品目标

1. **记录便捷**：让用户能在 10 秒内完成一笔收支的记账（选择分类 → 输入金额 → 保存）。
2. **洞察清晰**：通过图表直观展示用户的消费结构、收支趋势，辅助理性消费决策。
3. **体验愉悦**：以清新可爱的视觉风格与轻量交互，降低记账的枯燥感，提升持续使用的动力。

### 2.2 用户故事

1. 作为一位日常记账用户，我希望**快速新增一笔支出/收入**，以便随时记录、不遗漏每一笔流水。
2. 作为一位有预算意识的用户，我希望**按分类/时间查看收支统计图表**，以便了解钱花在了哪里。
3. 作为一位注重整理的用户，我希望**自定义收支分类与图标**，以便让记账符合自己的生活习惯。
4. 作为一位长期使用者，我希望**通过首页概览快速了解本月结余**，以便一目了然地掌握财务状况。
5. 作为一位偶尔记错的用户，我希望**编辑或删除已有账目**，以便修正错误记录，保持数据准确。

## 3. 技术规范

### 3.1 需求池（Requirements Pool）

**P0（必须实现）**

- 记录一笔收支：字段包括金额、类型（支出/收入）、分类、日期、备注（可选）。
- 首页账目列表：按日期倒序展示流水，展示每笔的金额、分类图标、备注。
- 分类管理：内置常用收支分类（餐饮、交通、购物、工资、理财等），可新增/删除自定义分类。
- 数据本地持久化：账目与分类数据保存在本地，应用重启后不丢失。
- 新增/编辑/删除账目：支持对已有流水进行修改与删除（删除需二次确认）。
- 本月概览：展示本月收入合计、支出合计、结余。

**P1（应该实现）**

- 收支统计图表：按分类占比（饼图/环形图）与按时间趋势（折线图/柱状图）展示。
- 时间筛选：按日/周/月/自定义区间查看账目与统计。
- 分类图标与配色：每个分类可配置图标和主题色，用于列表与图表展示。

**P2（可以后续实现）**

- 预算设置与超支提醒。
- 数据导出（CSV）与备份/恢复。
- 多账本、搜索/关键词过滤。
- 深色模式与主题皮肤切换。

### 3.2 UI 设计稿说明

**整体风格**：清新可爱（soft pastel 色调，如薄荷绿、奶油黄、樱花粉；圆角卡片、柔和阴影、Q 萌分类图标；字体圆润友好）。

**页面结构**：

1. **首页（账目列表）**
   - 顶部：本月结余卡片（大号数字 + 收入/支出摘要），采用渐变/浅色背景。
   - 中部：账目列表，按日期分组，每行显示分类图标、分类名、备注、金额（支出为负/红色系，收入为正/绿色系）。
   - 底部：悬浮「+」按钮（记账入口），固定于右下角。

2. **记账页（新增/编辑）**
   - 类型切换：支出 / 收入 分段选择。
   - 金额输入：大号数字键盘，实时显示金额。
   - 分类选择：网格图标选择器（Q 萌图标 + 分类名）。
   - 日期选择、备注输入框。
   - 底部：「保存」主按钮。

3. **统计页**
   - 顶部：时间范围切换（日/周/月）。
   - 中部：分类占比环形图 + 趋势折线/柱状图。
   - 底部：分类排行列表（金额与占比）。

4. **分类管理页**
   - 分类列表（图标 + 名称 + 类型），支持新增、编辑、删除。
   - 新增/编辑时选择图标与颜色。

### 3.3 待确认问题（Open Questions）

1. 数据是否需要云同步/多端同步，还是仅本地存储即可？
2. 金额与币种是否仅支持人民币，是否需要多币种支持？
3. 图表库与状态管理方案是否有既有技术偏好（如 Riverpod/Provider、fl_chart 等）？
4. 是否需要登录/账号体系，还是匿名本地使用？
5. 目标平台仅 Android，还是同时覆盖 iOS / Web？
